# NailMind 方案设计文档

本文以当前工作区为准。`app/`、`backend/`、`web-admin/` 和 `inference/` 分别对应 Android 客户端、业务后端、后台 Web 和 GPU 推理服务。

| 状态 | 含义 |
|---|---|
| 已实现 | 仓库中已有页面、接口、数据结构或测试 |
| 依赖环境 | 代码已经接入，运行需要模型密钥、社区登录态或 GPU |
| 后续演进 | 当前版本尚未落地 |

## 1. 项目背景与目标

### 1.1 要解决的问题

| 角色 | 当前问题 | 产品处理方式 |
|---|---|---|
| 消费用户 | 款式图好看，但无法判断放到自己手上的效果 | 小美导购、双路 AI 试戴、收藏和预约 |
| 门店商家 | 价格、库存、档期、咨询和预约分散 | 商家工作台统一维护门店供给 |
| 平台运营 | 社区趋势变化快，站内漏斗靠人工整理 | NailClaw 发现趋势，Ops Assistant 分析转化 |

```mermaid
flowchart LR
    community["社区帖子与互动数据"] --> nailclaw["NailClaw 趋势判断"]
    nailclaw --> review["运营审核候选款"]
    review --> catalog["平台款式库"]
    merchant["商家价格、库存与档期"] --> catalog
    catalog --> meimei["小美推荐与款式发现"]
    meimei --> tryon["GPU 与 GPT Image 2 双路试戴"]
    tryon --> booking["收藏、咨询与预约"]
    booking --> events["点击、收藏、试戴与预约事件"]
    events --> ops["Ops Assistant 漏斗诊断"]
    ops --> review
```

### 1.2 产品目标

| 目标 | 验证方式 |
|---|---|
| 用户更快看到本人上手效果 | 记录首张成功图片耗时和试戴成功率 |
| 单个模型失败时仍有可用结果 | GPU 与 GPT Image 2 独立保存状态和错误 |
| 趋势建议可以复核 | 每条建议保留原帖、图片和互动证据 |
| 运营动作可控 | 写操作使用白名单，并由运营确认 |
| 建议执行后可以复盘 | 按款式编号继续观察点击、试戴和预约 |

### 1.3 模型调研与选择

| 方案 | 实际观察 | 当前用途 |
|---|---|---|
| 豆包图像模型 | 响应快，部分结果会让皮肤发亮 | 前期对比 |
| Nano Banana | 生成质量好，国内代理与费用需要额外处理 | 效果对照 |
| Qwen Image 2.0 Pro | 效果与速度较均衡，国内 API 接入方便 | 趋势候选款商品图 |
| GPT Image 2 | 手部和背景保持较好，适合参考图编辑 | 双路试戴中的生图线路 |
| 独立 GPU 局部推理 | 甲面区域可控，能保留原手图结构 | 双路试戴中的可控线路 |
| Qwen3.7-Plus | 支持文字、图片理解和结构化输出 | 三个 Agent 与试戴质检 |

## 2. 总体架构

### 2.1 三端业务架构

```mermaid
flowchart TB
    subgraph client["Android 用户端"]
        browse["浏览与搜索"]
        assistant["小美"]
        tryon_ui["AI 试戴"]
        booking_ui["门店与预约"]
    end

    subgraph admin["Web 工作台"]
        merchant_ui["商家：门店供给与履约"]
        ops_ui["运营：款式、趋势、质检与策略"]
    end

    api["FastAPI 业务接口"]
    agents["小美、NailClaw、Ops Assistant"]
    gpu["独立 GPU 推理服务"]
    cloud["GPT Image 2 与 Qwen 模型"]
    data[("业务库、行为事件、图片与趋势证据")]

    browse --> api
    assistant --> api
    tryon_ui --> api
    booking_ui --> api
    merchant_ui --> api
    ops_ui --> api
    api --> agents
    api --> gpu
    api --> cloud
    api <--> data
    agents <--> data
```

### 2.2 系统分层

| 层次 | 组成 | 职责 |
|---|---|---|
| 交互层 | Android App、运营与商家 Web | 页面交互、结果展示、任务轮询 |
| 业务层 | 用户、款式、门店、供给、预约、试戴任务 | 权限检查、业务规则、数据聚合 |
| Agent 层 | 小美、NailClaw、Ops Assistant | 理解目标、准备上下文、调用工具 |
| 模型层 | GPU、GPT Image 2、Qwen Image、Qwen3.7-Plus | 图像推理、图像生成、多模态理解 |
| 数据层 | 业务数据、事件、图片、趋势证据 | 保存状态和分析依据 |

### 2.3 模型与业务边界

```mermaid
flowchart LR
    app["App 或 Web"] --> api["统一业务 API"]
    api --> rules["权限、状态和规则校验"]
    rules --> adapter["模型适配层"]
    adapter --> gpu["GPU 局部推理"]
    adapter --> gpt["GPT Image 2"]
    adapter --> qwen["Qwen 模型"]
    gpu --> persist["结果校验与落库"]
    gpt --> persist
    qwen --> persist
    persist --> api
```

客户端不直接调用模型服务。底层模型替换时，App 和 Web 接口保持不变。

## 3. 双路并发 AI 试戴

### 3.1 并发时序

```mermaid
sequenceDiagram
    actor U as 用户
    participant A as Android App
    participant B as 业务后端
    participant G as GPU 服务
    participant P as GPT Image 2
    participant D as 数据库

    U->>A: 选择款式并上传手图
    A->>B: 创建试戴任务
    B->>D: 创建主任务和两个结果槽位
    par GPU 分支
        B->>B: 准备五甲片素材
        B->>G: 提交手图和素材包
        G-->>B: 返回局部推理结果
    and 生图分支
        B->>P: 提交手图和款式图
        P-->>B: 返回生图结果
    end
    B->>D: 按真实完成顺序保存结果
    B-->>A: 第一张成功后即可查看
    A->>B: 继续轮询另一条线路
    B-->>A: 返回完整结果或单路错误
```

### 3.2 任务状态

```mermaid
stateDiagram-v2
    [*] --> preparing: 创建任务
    preparing --> rendering: 公共输入就绪
    preparing --> failed: 手图或款式无效
    rendering --> first_result_ready: 任一线路成功
    rendering --> failed: 两条线路都失败
    first_result_ready --> completed: 两条线路都已结束
    completed --> [*]
    failed --> [*]
```

| 结果情况 | 用户看到的内容 | 主任务结果 |
|---|---|---|
| 两条线路成功 | 先显示首张，随后加入第二张 | 完成 |
| GPU 失败，GPT 成功 | 显示生图结果 | 完成，并保留 GPU 错误 |
| GPT 失败，GPU 成功 | 显示 GPU 结果 | 完成，并保留 GPT 错误 |
| 两条线路失败 | 提示重新生成 | 失败 |

### 3.3 首图耗时

```text
firstResultDurationMs = min(所有成功结果的 duration_ms)
```

| 指标 | 口径 |
|---|---|
| 首图耗时 | 第一张成功图片从任务开始到完成的时间 |
| Provider 耗时 | GPU 和 GPT Image 2 各自的完成时间 |
| 双路失败次数 | 两条线路都失败的任务数 |

### 3.4 GPU 路线

```mermaid
flowchart LR
    subgraph offline["款式入库阶段"]
        style["款式图"] --> sam3["SAM3 分割指甲"]
        sam3 --> gate["置信度、面积、长宽比与去重门槛"]
        gate --> tps["Mask 内缩与 TPS 展平"]
        tps --> pack["五指透明甲片素材包"]
        pack --> manual["运营复核"]
    end

    subgraph online["用户试戴阶段"]
        hand["用户手图"] --> yolo["YOLO11s-seg 定位甲面"]
        manual --> align["按手指选择甲片"]
        yolo --> align
        align --> warp["缩放、旋转与透视配准"]
        warp --> blend["局部融合与边缘修复"]
        blend --> result["合回原分辨率手图"]
    end
```

| 后端 | 当前定位 |
|---|---|
| `local_inpaint` | 仓库提供的生产环境示例 |
| `reference_local_edit` | 可选参考图增强线路 |
| FLUX.2 Klein | 评测中的可选线路 |

### 3.5 GPT Image 2 路线

```mermaid
flowchart LR
    hand["用户手图作为主图"] --> prompt["限制只编辑甲面"]
    style["款式图作为参考图"] --> prompt
    prompt --> submit["提交异步生图任务"]
    submit --> poll["轮询任务状态"]
    poll --> download["下载结果图"]
    download --> quality["六项质量检查"]
```

提示词要求迁移颜色、图案、甲型、长度、装饰和光泽，同时保留手型、肤色、姿势、背景、光线和构图。模型仍可能重绘非甲面区域，因此结果会进入质检。

### 3.6 结果质检

| 检查项 | 判断内容 |
|---|---|
| 款式还原 | 颜色、纹理、装饰和整体风格是否接近目标款式 |
| 甲面贴合 | 图案是否落在甲面内，边缘是否自然 |
| 手指数量 | 是否出现多指、少指或结构错误 |
| 皮肤保持 | 肤色和皮肤质感是否明显变化 |
| 姿态保持 | 手型、方向和构图是否被大幅改动 |
| 背景保持 | 原背景是否被无关内容替换 |

质检在首图展示后执行，不延长用户等待首张图片的时间。

### 3.7 当前任务执行限制

| 当前实现 | 风险 | 后续演进 |
|---|---|---|
| FastAPI 进程内后台任务和线程池 | 服务在生成期间退出时需要重试 | 迁移到持久化任务队列 |
| 数据库保存任务与结果状态 | 可以查询历史状态，但不能恢复已中断的执行器 | 独立 Worker 领取和续跑任务 |

## 4. 三个 Agent

### 4.1 分工

| Agent | 输入 | 工具范围 | 输出 |
|---|---|---|---|
| 小美 | 对话、偏好、最近手图、在架款式 | 手图分析、知识检索、款式检索、App 入口 | 回复、分析、款式卡片和跳转入口 |
| NailClaw | 社区帖子、图片、互动量、款式库 | 采集、证据检查、款式匹配、候选图生成 | 趋势证据、加推建议或新款候选 |
| Ops Assistant | 曝光、点击、收藏、试戴、预约 | 指标查询、首页推荐、款式状态、推荐组 | 经营诊断、待确认方案和执行结果 |

### 4.2 共同运行约定

```mermaid
flowchart LR
    request["请求入口"] --> context["上下文与短期记忆"]
    context --> planner["Planner 判断任务"]
    planner --> llm["模型理解或结构化输出"]
    planner --> tools["Tool Manager 调用白名单工具"]
    llm --> validate["字段、枚举和范围校验"]
    tools --> validate
    validate --> persist["业务状态写入"]
    persist --> response["文字、卡片和页面入口"]
```

Planner、模型适配器、Tool Manager 和 Memory 是共同约定，每个 Agent 在自己的目录中实现这些职责。模型不能绕过工具层改变款式、候选款或推荐位。

### 4.3 记忆和流式输出

| Agent | 短期记忆 | 持久数据 |
|---|---|---|
| 小美 | 最近 8 条有效对话、偏好、手图和上一轮分析 | 用户资料、手图和行为记录 |
| NailClaw | 当前不额外保存会话状态 | 趋势主题、原帖、候选款和建议 |
| Ops Assistant | 最近的分析与执行摘要 | 日指标、推荐组、动作结果和事件 |

```mermaid
sequenceDiagram
    participant UI as 页面
    participant API as Agent 流式接口
    participant M as 模型或规则层
    UI->>API: 发起请求
    API-->>UI: status
    loop 生成说明
        M-->>API: 文本片段
        API-->>UI: delta
    end
    API-->>UI: result 结构化结果
    API-->>UI: done
```

### 4.4 小美

```mermaid
flowchart LR
    input["用户文字或手图"] --> intent{"明确意图？"}
    intent -->|是| rules["规则和槽位识别"]
    intent -->|否| model["Qwen3.7-Plus 解析"]
    rules --> rag["检索美甲知识"]
    model --> rag
    rag --> vision{"有手图？"}
    vision -->|是| analyze["检查手部并分析肤色、手型与甲床"]
    vision -->|否| catalog["查询在架款式"]
    analyze --> catalog
    catalog --> rank["按明确条件、偏好和知识词评分"]
    rank --> output["回复、款式卡片和 App 入口"]
```

模型不可用时，明确意图路由、知识检索和款式匹配仍由规则完成。手图无效时，App 引导用户重传或改用文字描述。

### 4.5 NailClaw

```mermaid
flowchart LR
    collect["采集近期图片帖子"] --> clean["去除过期、重复和非美甲内容"]
    clean --> cluster["按颜色、工艺和风格聚类"]
    cluster --> evidence{"达到基础证据门槛？"}
    evidence -->|否| observe["只保留观察结论"]
    evidence -->|是| vision["Qwen3.7-Plus 多模态判断"]
    vision --> trend{"达到趋势质量门槛？"}
    trend -->|否| observe
    trend -->|是| match{"款式库已有相似款？"}
    match -->|是| boost["生成加推或恢复建议"]
    match -->|否| generate["生成脱敏候选商品图"]
    generate --> pending["进入待审核候选款"]
```

| 门槛 | 当前值 |
|---|---:|
| 不同帖子数 | 至少 2 条 |
| 可复核图片 | 至少 1 张 |
| 最高点赞 | 至少 100 |
| 综合互动 | 至少 500 |
| 有效参考图 | 至少 2 张 |
| 甲面可见度 | 不低于 0.70 |
| 跨帖一致性 | 不低于 0.60 |
| 商业复刻度 | 不低于 0.65 |

综合互动按“点赞 + 2 × 收藏 + 3 × 评论”计算。候选图不会直接使用原帖人物图，原帖只作为运营复核证据。

### 4.6 Ops Assistant

```mermaid
flowchart LR
    metrics["读取款式日指标"] --> rates["计算点击率、试戴率、预约率和综合分"]
    rates --> mode{"任务模式"}
    mode --> query["自然语言查询"]
    mode --> discover["自动发现漏斗断点"]
    mode --> audience["分析匿名偏好分组"]
    mode --> plan["生成待确认方案"]
    mode --> evaluate["执行后评估"]
    query --> explain["模型生成说明"]
    discover --> explain
    audience --> actions["规则生成动作参数"]
    plan --> actions
    actions --> confirm{"运营确认？"}
    confirm -->|否| preview["只预览"]
    confirm -->|是| tools["工具层再次校验并执行"]
    tools --> evaluate
```

| 可写操作 | 约束 |
|---|---|
| 修改款式状态 | 款式必须存在，状态迁移合法 |
| 调整首页推荐位 | 款式已上架并有展示图 |
| 创建或更新人群推荐组 | 排序、周期和流量参数合法 |

场景分类由款式标签决定，Agent 不能把款式直接写入“通勤”或“约会”等分类。

### 4.7 输出和权限约束

| 位置 | 处理方式 |
|---|---|
| 模型输入 | 只传当前任务需要的对话、图片、指标和候选款 |
| 模型输出 | 固定 JSON 字段，检查枚举、分数、数量和工具名 |
| 数据读取 | 每个 Agent 只读自己的业务范围 |
| 数据写入 | NailClaw 只建待审核候选，Ops 写操作需要运营确认 |
| 失败处理 | 小美回到规则结果，NailClaw 停止建候选，Ops 返回规则诊断 |

## 5. 数据回流与验证

### 5.1 数据回流

```mermaid
flowchart LR
    posts["社区趋势证据"] --> candidate["候选款"]
    candidate --> review["运营审核"]
    review --> style["正式款式"]
    style --> recommend["小美与首页推荐"]
    recommend --> behavior["点击、收藏、试戴和预约"]
    behavior --> daily["款式日指标"]
    daily --> diagnosis["Ops Assistant 诊断"]
    diagnosis --> review
```

候选款、正式款式和行为指标通过款式编号关联，运营可以检查一次上新或加推后的实际变化。

### 5.2 指标口径

| 观察对象 | 指标 |
|---|---|
| 用户 | 试戴发起率、首图耗时、试戴后收藏率、试戴后预约率 |
| 模型 | 分线路成功率、耗时、款式还原、甲面贴合、手部与背景保持 |
| NailClaw | 证据完整率、候选通过率、候选入库后的转化 |
| Ops Assistant | 诊断与真实指标一致性、动作执行结果、执行后变化 |

### 5.3 验证矩阵

| 验证对象 | 场景 | 检查内容 |
|---|---|---|
| 双路试戴 | GPU 先完成、GPT 先完成、单路失败、双路失败 | 首图展示、横向翻页、耗时和错误提示 |
| 图像质量 | 固定手图和固定款式 | 六项质检和隐藏模型名称的人工对比 |
| 小美 | 明确意图、模糊意图、有效手图、无效手图 | 路由、推荐、降级和 App 入口 |
| NailClaw | 证据不足、已有相似款、新趋势 | 停止建候选、加推建议、新候选 |
| Ops Assistant | 查询、诊断、生成方案、确认执行、复盘 | 指标准确性、动作白名单和权限 |

仓库已有基准脚本、推理样例和自动化测试。平均耗时、成功率和质量分必须来自同一版本、同一批样本；没有有效样本时显示“待评测”。

```mermaid

    participant A as Android App
    participant B as 业务后端
    participant M as 商家工作台

    O->>B: 提交待确认运营方案

```
